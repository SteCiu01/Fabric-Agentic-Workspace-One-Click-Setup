How it works: local files and live tools together

  1. Per session, pull locally only the items you need, then do mixed work: edit some files locally, touch others live.
  2. Both edit paths converge on the same DEV workspace and follow the same review and promotion lifecycle.
  3. Commit the workspace state, review history, and revert if needed.
  4. Promote by pull request (dev to prod), keep prod settings intact, then sync the prod branch to the Fabric PROD workspace.
Golden rule: keep local = live. Re-pull from the live workspace before each new job so your local folder matches it exactly. This avoids drift.
Shared safety anchor. Commit the validated DEV workspace state, review changes, and revert when needed.

Best for

  • Day-to-day work that blends local file edits with live checks
  • Situations where some items are easier as files and others are better live
  • Comparing live data and validating changes
  • Iterative development across multiple item types
  • Teams that need both flexibility and control
