How it works: file-first editing

  1. Pull the Fabric items you need into your local folder with the Fabric extension.
  2. Edit the real files locally: TMDL, DAX, PBIR, pipeline JSON, notebooks, SQL and more.
  3. Push the changes back to the DEV workspace with the Fabric extension.
  4. Test everything in the Fabric DEV workspace and adjust manually if needed.
  5. Commit the workspace state to Azure DevOps (dev branch): versioned and reversible.
  6. Promote through a pull request (dev to prod), then sync the prod branch to Fabric PROD.
Shared safety anchor. Fabric Git commits capture the DEV workspace state after validation. You can review history and revert DEV when needed.

Best for

  • Large semantic model refactoring
  • Bulk or structured edits
  • Code-style reviews and diff workflows
  • Offline or low-connectivity work
  • Clean, auditable file history
  • Teams that prefer file-based workflows
